# נגישות — מה נבדק, איך, ומה עוד לא

## החובה

חוק שוויון זכויות לאנשים עם מוגבלות ותקנות נגישות השירות מחייבים אתר שנותן
שירות לציבור לעמוד ב**ת״י 5568 ברמה AA**, המבוסס על WCAG 2.0. סעיף 35 לתקנות
מחייב גם **הצהרת נגישות** מפורסמת, הכוללת את התאמות הנגישות, המגבלות הידועות
ודרך יצירת קשר.

**הפטור לעסקים קטנים לא חל עלינו.** הפטור לפי מחזור (מתחת ל-120,000 ₪ פטור
זמני; 120,000–1,000,000 ₪ פטור זמני) חל על **הנגשת אתרים קיימים**. אתר חדש
נבנה נגיש מלכתחילה, וזו גם ההחלטה הנכונה: להנגיש בדיעבד יקר פי כמה.

## איך זה נבדק

הבדיקה אוטומטית ומריצים אותה מול הבילד, לא מול הערכה:

```bash
cd web
npm run build
DEMO_MODE=true npx next start -p 3111 &
node a11y-audit.mjs   # axe-core על כל עמוד
node rtl-audit.mjs    # RTL, גלישה אופקית, גודל מטרות, ניווט מקלדת
```

`a11y-audit.mjs` מריץ את מנוע `axe-core` — אותו מנוע שבודקי נגישות משתמשים בו —
עם תגי `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` ו-`best-practice`, על עשרת
העמודים, כשהוא מחובר כעסק כדי שהמסכים הסגורים ייבדקו גם הם.

## מה עוד לא נעשה

- **בדיקה ידנית מול קורא מסך על ידי בודק מוסמך.** בדיקה אוטומטית תופסת חלק
  מהבעיות, לא את כולן. זה הפער המשמעותי היחיד שנותר, והוא רשום גם בהצהרה.
- תוכן שמשתמשים מזינים (שמות ותיאורי קמפיינים) אינו בשליטתנו.
- אין גרסה בשפות נוספות.

## מה ששובר נגישות בלי לשים לב

- צבע חדש → להריץ את הבדיקה. אל תסמכו על העין; 4.4 ו-4.6 נראים זהים.
- שקיפות על טקסט (`text-ink/80`, `opacity-60`) — זה מה ששבר את שתי הבדיקות
  הראשונות. עדיף טוקן צבע מלא.
- מאפייני פריסה פיזיים (`ml-`, `pr-`) במקום לוגיים (`ms-`, `pe-`) — נשברים ב-RTL.
- כותרת שמדלגת דרגה כדי להיראות קטנה יותר. לעצב עם `text-*`, לא עם `h4`.
- **משתני `next/font` חייבים לשבת על `<html>`, לא על `<body>`.** ה-`@theme` של
  Tailwind מגדיר את `--font-sans` ב-`:root`, ומשתנה CSS נפתר מול האלמנט של
  עצמו. עם המשתנים על `<body>` — צאצא — `:root` לא מצא כלום, ההצהרה נפסלה,
  וכל הכותרות באתר נפלו בשקט לפונט המערכת. שום בדיקה אוטומטית לא תופסת את זה;
  רק להסתכל.

## תפריט הנגישות

`components/AccessibilityMenu.tsx` — נכתב כאן ולא נקנה כתוסף חיצוני. תוספי
overlay מוסיפים סרגל ומצהירים על עמידה בתקן, אבל הם פורסים ARIA על מבנה שהם
לא מבינים, ומשתמשי קוראי מסך מדווחים שוב ושוב שהם מרעים את המצב. כל פקד
בתפריט משנה CSS משלנו, והעמודים עצמם עוברים axe גם בלעדיו.

מה יש בו: גודל טקסט (100%–150%), ניגודיות גבוהה, הדגשת קישורים, עצירת
אנימציות, גופן קריא, איפוס, וקישור להצהרה. ההעדפות נשמרות ב-localStorage.

**האתר נבדק גם עם כל ההגדרות דלוקות** (150% טקסט + ניגודיות גבוהה): 0 הפרות.
זו הבדיקה שחשובה — מצב ניגודיות שנראה שונה אבל לא עומד ביחסים הוא חסר ערך.

## ביצועים — למה זה היה איטי

`/campaigns` לקח 1.28 שניות בעקביות. הסיבה לא הייתה בקוד אלא בגאוגרפיה:
הדאטה בייס ב-`eu-west-1` (אירלנד), והפונקציות של Vercel רצו ב-`iad1`
(וושינגטון). כל שאילתה חצתה את האטלנטי — כ-90ms הלוך-חזור — והעמוד עשה כ-13.

מה שתוקן, לפי סדר הגודל:

1. **`"regions": ["dub1"]` ב-`vercel.json`** — הפונקציות רצות ליד הדאטה בייס.
2. **ביטול שאילתות N+1** — `listBusinessesByIds`, `listCodesByCampaignIds`,
   `listUsersByIds`, `listCampaignsByIds`. עמוד עם N קמפיינים עולה עכשיו מספר
   קבוע של שאילתות במקום 2N+2.
3. **צמצום ה-middleware** לנתיבים שקוראים session בלבד. כל הרצה שלו היא קריאת
   רשת ל-Supabase Auth, ודף הבית והדפים המשפטיים שילמו עליה לחינם.
4. **`next/font`** במקום שלושה `<link>` ל-Google Fonts שחסמו ציור ראשון.

| עמוד | לפני | אחרי |
|---|---|---|
| `/campaigns` | 1.28s | ~0.43s |
| `/` | 0.37s | ~0.30s |
| `/legal/terms` | 0.29s | ~0.23s |

**הכלל שחשוב לזכור:** מספר הפניות לדאטה בייס בעמוד הוא זמן הטעינה שלו. לולאה
עם `await` בפנים היא N פניות; `Promise.all` על אותה לולאה עדיין N. רק שאילתה
אחת עם `in (...)` היא אחת.
